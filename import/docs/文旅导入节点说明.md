## 一、node_entry（入口识别与路由）

> 节点位置：`app/process/tourism_import/agent/nodes/node_entry.py`
> 所属图：文旅导入图 kb_tourism_import_app（app/process/tourism_import/agent/main_graph.py）
> 调用服务：`app/rag/common/entry_service.py`

### 1. 导入与配置
引入必要的库（`node_log`、`add_running_task`/`add_done_task`、`TourismImportGraphState`、`resolve_input_file`）及配置参数。路由开关用到的表格/文本扩展名常量来自 `app/rag/common/chunk_config.py` 的 `SUPPORTED_TABLE_EXTENSIONS` 与 `SUPPORTED_TEXT_EXTENSIONS`。

- `node_entry.py:1` `from app.shared.runtime.logger import node_log`
- `node_entry.py:2` `from app.shared.utils.task_utils import add_done_task, add_running_task`
- `node_entry.py:3` `from app.process.tourism_import.agent.state import TourismImportGraphState`

- `app/rag/common/entry_service.py:5-9` `from app.rag.common.chunk_config import (SUPPORTED_TABLE_EXTENSIONS, SUPPORTED_TEXT_EXTENSIONS)`
- 配置常量：`SUPPORTED_TABLE_EXTENSIONS = {".xlsx", ".xls", ".csv"}`（`chunk_config.py:26`）、`SUPPORTED_TEXT_EXTENSIONS = {".txt", ".json", ".html", ".htm", ".docx"}`（`chunk_config.py:31`）

### 2. 节点入口函数
`node_entry(state)` 是 LangGraph 图的 Entry Point，用 `@node_log("node_entry")` 记录调用日志，先 `add_running_task` 标记任务开始，调用 `resolve_input_file(state)` 后 `add_done_task` 标记完成，最后原样返回更新后的 state（`node_entry.py:7-16`）。
输出字段：按后缀决定打开四个路由开关之一 —— `is_md_read_enabled` / `is_pdf_read_enabled` / `is_table_read_enabled` / `is_text_read_enabled`，并补全 `md_path`/`pdf_path`/`file_title`（`app/process/tourism_import/agent/state.py:10-25`）。main_graph 中由 `after_entry_node` 依据这些开关做条件边路由（`main_graph.py:50-72`）。

### 3. Service 总入口
`resolve_input_file(state)` 是总入口，负责识别文件类型并初始化状态路由开关，一句话完成「按后缀决定走 md / pdf / 表格 / 纯文本 四条路径，非法类型终止流程」（`entry_service.py:13-19`）。

### 4. 步骤 1: 获取文件本地路径
从 state 中读取 `local_file_path`，作为本次识别的唯一输入（`entry_service.py:20`）。

### 5. 步骤 2: 校验文件路径是否为空
若 `local_file_path` 为空，记录 warning「文件路径为空」并直接返回原 state，终止当前导入流程（`entry_service.py:22-25`）。

### 6. 步骤 3: 统一初始化四个路由开关
先把 `is_md_read_enabled` / `is_pdf_read_enabled` / `is_table_read_enabled` / `is_text_read_enabled` 全部置为 False，再按后缀打开其中一个（`entry_service.py:27-32`）。

### 7. 步骤 4: 按文件后缀识别文件类型并设置路由
按优先级逐个分支判断（`entry_service.py:34-60`）：
- `.md` 结尾 → 设置 `md_path`，打开 `is_md_read_enabled`（`entry_service.py:35-37`）
- `.pdf` 结尾 → 设置 `pdf_path`，打开 `is_pdf_read_enabled`（`entry_service.py:39-41`）
- 后缀 ∈ `SUPPORTED_TABLE_EXTENSIONS`（xlsx/xls/csv）→ 打开 `is_table_read_enabled`，跳过 PDF/MD 解析与切分（`entry_service.py:43-45`）
- 后缀 ∈ `SUPPORTED_TEXT_EXTENSIONS`（txt/json/html/htm/docx）→ 打开 `is_text_read_enabled`，转 Markdown 后复用标题切分管线（`entry_service.py:47-49`）
- 其他类型 → 显式抛 `ValueError("不支持的文件类型...")` 让任务标记失败，避免静默「completed」误导用户（`entry_service.py:55-60`）

### 8. 步骤 5: 自动提取文件标题并返回
用 `Path(local_file_path).stem` 提取不带后缀的文件名写入 `state["file_title"]`，随后返回补全后的 state（`entry_service.py:62-66`）。

### 9. 单元测试
节点文件 `__main__` 内置 5 个场景的独立测试（`node_entry.py:19-51`），均通过 `create_default_state` 构造带不同 `local_file_path` 的最小 state 后调用 `node_entry` 并断言路由开关：
1. `兵马俑.pdf` → 断言 `is_pdf_read_enabled=True` 且表格开关关闭；
2. `北欧文化.md` → 断言 `is_md_read_enabled=True`；
3. `景点清单.xlsx` → 断言 `is_table_read_enabled=True`；
4. `data.csv` → 断言 `is_table_read_enabled=True`；
5. `xxx.txt` → `.txt` 现已被纳入 `SUPPORTED_TEXT_EXTENSIONS`，因此会打开 `is_text_read_enabled=True`；该测试仅断言 md/pdf/table 三个开关全为 False（通过），用于确认文本类后缀不会错误命中其他分支。

直接运行 `python app/process/tourism_import/agent/nodes/node_entry.py` 即可执行，无需外部服务依赖。

## 二、node_text_parse（文本类转 Markdown：txt/json/html/htm/docx）

> 节点位置：`app/process/tourism_import/agent/nodes/node_text_parse.py`

### 1. 导入与配置
引入必要的库（`node_log`、`add_running_task`/`add_done_task`、`TourismImportGraphState`、`parse_text_to_markdown`）及配置参数。

- `node_text_parse.py:1` `from app.shared.runtime.logger import node_log`
- `node_text_parse.py:2` `from app.shared.utils.task_utils import add_done_task, add_running_task`
- `node_text_parse.py:3` `from app.process.tourism_import.agent.state import TourismImportGraphState`
- `node_text_parse.py:4` `from app.rag.common.text_parse_service import parse_text_to_markdown`
- `app/rag/common/text_parse_service.py:18` `from app.rag.common.chunk_config import CELL_MAX_LEN, SUPPORTED_IMAGE_EXTENSIONS`
- 配置常量：`CELL_MAX_LEN = 2000`（`chunk_config.py:28`）、`SUPPORTED_IMAGE_EXTENSIONS`（图片格式白名单，`chunk_config.py:14`）；service 内部另有 `TEXT_MAX_CHARS = 1_000_000` 单文件读取上限（`text_parse_service.py:19`）

### 2. 节点入口函数
`node_text_parse(state)` 是 LangGraph 节点入口，`@node_log("node_text_parse")` 记录日志，先 `add_running_task` 调用 `parse_text_to_markdown(state)`，成功后 `add_done_task`，返回更新后的 state（`node_text_parse.py:7-16`）。
输入依赖 `local_file_path`（可选 `local_dir`）；输出写入 `md_content`、`md_path`（转换后的 .md 落盘路径）、`file_title`、`source_type`（`text_parse_service.py:359-362`）。docx/html 解析时顺带抽取内嵌图片落盘 `images/` 并插 `![](images/xxx)` 引用；图中纯文本分支由 `node_entry` 路由至此，下游经 node_md_img 增强（docx/html 有图时走 VLM 摘要+MinIO，txt/json 无图时安全早返回）后接 `node_document_split` 复用标题切分管线（`main_graph.py:76`，text_parse → node_md_img）。

### 3. Service 总入口
`parse_text_to_markdown(state)` 是总入口，负责把 txt/json/html/htm/docx 五类文件解析为 Markdown 内容并落盘（`text_parse_service.py:320-373`）。

### 4. 步骤 1: 读取文件路径并确定标题与来源类型
读取 `local_file_path`，为空则记录 error 并置 `md_content=""` 直接返回；`file_title` 缺失时用 `Path(file_path).stem` 兜底；`source_type` 取后缀小写（txt/json/html/htm/docx）（`text_parse_service.py:323-329`）。图片输出目录约定为 `local_dir/images/`（与 enrich_markdown_images 扫描约定一致，`text_parse_service.py:332-333`）。

### 5. 步骤 2: 读取文本内容（utf-8/GBK 兜底 + 上限截断）
`_read_text_file(file_path)` 仅用于 txt/json，优先 utf-8 读取，遇 `UnicodeDecodeError` 改用 GBK 兜底，最后统一截断到 `TEXT_MAX_CHARS`（100 万字符）防止超大文件拖垮服务（`text_parse_service.py:22-30`）。docx 为二进制格式，不走该函数，直接读文件路径。

### 6. 步骤 3: 转换为 Markdown（按来源类型分派）
- `txt`：直接包一层一级标题 `# {file_title}`，保证切分时至少产出带标题的块（`text_parse_service.py:350`）；
- `json`：`json.loads` 解析后调 `_json_to_markdown`——数组按记录生成 `## 记录 N` 小节、对象按顶层 key 生成 `## key` 小节，字段格式化为 `- key: value`（嵌套值 pretty-dump 并截断到 `CELL_MAX_LEN`），首行为 `# {file_title}`（`text_parse_service.py:341-343`、`43-68`）；
- `html` / `htm`：`_html_to_markdown` 用 BeautifulSoup 抽取正文（去除 script/style/nav/footer/header/aside/iframe 等噪声），优先取 `article`/`main`/`body`，再经 markdownify 转 Markdown；从 `<title>` 或 `<h1>` 提取标题，确保开头有 `#` 一级标题（`text_parse_service.py:251-317`）。**图片处理**：转换前逐个 `<img>` 解析 src——`data:` URI base64 解码、本地相对路径按 html 父目录解析、远程 http(s) urllib 下载（超时 10s），统一落盘 `images/`（`_resolve_and_save_html_image`，`text_parse_service.py:203-248`）并把 src 重写为 `images/xxx` 产出 `![](images/xxx)` 引用；失败仅跳过该图、保留原 src；
- `docx`：`_docx_to_markdown` 用 python-docx 按文档流顺序提取标题/段落/列表/表格，标题按样式映射为 `##`/`###` 等，表格转为 Markdown 表格（`text_parse_service.py:130-201`）。**图片处理**：逐段扫 `<a:blip r:embed>` 与 `<v:imagedata r:id>`（VML 用 Clark 全名空间），经 `doc.part.related_parts` 取图片 part 落盘 `images/`（`text_parse_service.py:71-127`），在对应段落位置插 `![图N](images/xxx)` 引用，同图多引去重为一份。

### 7. 步骤 4: 转换结果落盘并回填 state
`local_dir` 缺省时用源文件所在目录，把转换后的 Markdown 写入 `{local_dir}/{file_title}.md`；随后回填 `md_content`、`md_path`、`file_title`、`source_type`，返回 state（`text_parse_service.py:352-362`）。`md_path` 供 `node_document_split` 的切块备份逻辑使用。

### 8. 步骤 5: 异常降级处理
`json.JSONDecodeError`（非法 JSON）记录 error 并置 `md_content=""` 返回；其他异常同样置空并带堆栈记录 error。空内容会在下游切块/入库校验处终止该任务，不影响同批其他文件（`text_parse_service.py:366-372`）。

### 9. 单元测试
节点文件 `node_text_parse.py` **没有** `__main__` 自检块，冒烟验证可走以下任一方式：
- 直接运行 service 的 `__main__`（`text_parse_service.py:225-273`）：用 `tempfile.TemporaryDirectory` 构造 txt / json 数组 / json 对象 / 非法 json 四类输入，分别断言 `md_content` 首行、`source_type`、记录小节与字段格式；
- 或运行整图 `app/process/tourism_import/agent/main_graph.py`（其 `__main__` 读取 `doc/兵马俑.pdf` 等样本），指定文本类文件触发 `node_entry → node_text_parse → node_document_split` 分支，观察日志中切片数量。

- 配置常量：`MINERU_MODEL_VERSION = "vlm"`（`chunk_config.py:16`）、`MINERU_POLL_TIMEOUT_SECONDS = 600`（`chunk_config.py:17`）、`MINERU_POLL_INTERVAL_SECONDS = 3`（`chunk_config.py:18`）、`MINERU_DOWNLOAD_TIMEOUT_SECONDS = 30`（`chunk_config.py:19`）

### 2. 节点入口函数
`node_pdf_to_md(state)` 是 LangGraph 节点入口，`@node_log("node_pdf_to_md")` 记录日志，先 `add_running_task` 再调用 `parse_pdf_to_markdown(state)`，成功后 `add_done_task`，返回更新后的 state（`node_pdf_to_md.py:13-22`）。
输入依赖 state 中的 `pdf_path`、`local_dir`；输出写入 `md_path`、`md_content`（`pdf_parse_service.py:151-152`），供下游 `node_md_img` 使用（`main_graph.py:76`）。

### 3. Service 总入口
`parse_pdf_to_markdown(state)` 是总入口，串联「校验 → 上传并轮询 MinerU → 下载解压提取 Markdown → 回填 state」四个子步骤（`pdf_parse_service.py:142-153`）。

### 4. 步骤 1: 校验 PDF 路径与输出目录
`validate_pdf_paths(state)` 读取 `pdf_path` 与 `local_dir`：路径为空直接抛 `ValueError`；`local_dir` 缺省时回填默认值 `PROJECT_ROOT/output`；`pdf_path` 文件不存在抛 `FileNotFoundError`；`local_dir` 不存在则主动 `mkdir(parents=True, exist_ok=True)` 创建，返回 (pdf 路径对象, 输出目录对象)（`pdf_parse_service.py:21-41`）。

### 5. 步骤 2: 上传 PDF 到 MinerU 并轮询解析结果
`upload_pdf_and_poll(pdf_path_obj)` 先校验 `mineru_gateway` 的 base_url/api_key 配置，调用 `POST {base_url}/file-urls/batch` 申请上传地址（携带 `model_version=MINERU_MODEL_VERSION`），拿到 `file_upload_url` 与 `batch_id` 后用 PUT 上传 PDF 二进制（`pdf_parse_service.py:44-72`）。随后轮询 `GET /extract-results/batch/{batch_id}`：状态为 `done` 时返回 `full_zip_url`，`failed` 抛异常，期间对 5xx 网络错误和瞬时异常做 `interval_time` 间隔重试，超时 `MINERU_POLL_TIMEOUT_SECONDS` 抛 `TimeoutError`（`pdf_parse_service.py:74-109`）。

### 6. 步骤 3: 下载解析结果压缩包并解压提取 Markdown
`download_and_extract_markdown(zip_url, local_dir_path_obj, stem)` 下载 zip 到 `{local_dir}/{stem}_result.zip`，删除旧目录后解压到 `{local_dir}/{stem}/`，在解压目录内 `rglob("*.md")` 查找 Markdown 文件：优先按文件名等于 PDF stem 定位，其次找 `full.md`，最后兜底取第一个 md 文件，并统一重命名为 `{stem}.md`（`pdf_parse_service.py:112-139`）。

### 7. 步骤 4: 回填 md_path 与 md_content 到 state
`parse_pdf_to_markdown` 将解压得到的 md 文件路径写入 `state["md_path"]`，并把文件内容按 utf-8 读取写入 `state["md_content"]`，返回更新后的 state（`pdf_parse_service.py:151-153`）。

### 8. 单元测试
节点文件 `__main__` 使用 `doc/兵马俑.pdf` 作为测试样本（`node_pdf_to_md.py:25-38`）：通过 `create_default_state` 构造 state（`pdf_path` 指向 `PROJECT_ROOT/doc/兵马俑.pdf`，`local_dir` 指向 `PROJECT_ROOT/output`）。若测试文件不存在则打错误日志并提示将 PDF 放入 doc 目录；存在则直接调用 `node_pdf_to_md(test_state)` 验证转换流程，成功后 `output/兵马俑/兵马俑.md` 可供后续节点测试使用。运行需真实 MinerU 服务。

### 2. 节点入口函数
`node_md_img(state)` 是 LangGraph 节点入口，`@node_log("node_md_img")` 记录日志，先 `add_running_task` 调用 `enrich_markdown_images(state)`，成功后 `add_done_task`，返回更新后的 state（`node_md_img.py:8-17`）。
输入依赖 `md_path`（必填）与 `md_content`；输出覆写 `md_content`（图片被替换为「AI 摘要 + 在线 URL」）并更新 `md_path` 为增强后的 `_new.md` 文件（`markdown_image_service.py:32-33`）。在图中承接 `node_pdf_to_md` 或 `node_entry` 的 md 分支，下游接 `node_document_split`（`main_graph.py:76-77`）。

### 3. Service 总入口

`parse_metadata(raw, file_title)` 先剥离可能的 ```json 代码块标记，用 `TourismMetadata.model_validate_json` 校验；`item_name` 为空时用 `file_title` 兜底；解析成功后调用 `normalize_extra` 对 `extra` 做键名白名单清洗（剔除脏键，无专属模型类型清空）；任何解析异常均降级为 `TourismMetadata(item_name=file_title, content_type=OPERATION_MATERIAL)`（推荐运营资料），保证导入不中断（`tourism_meta_extract_service.py:52-74`）。

### 7. 步骤 4: 元数据回填到 state 与每个 chunk
把 `item_name`/`content_type` 写入 state 级字段并 `state["tourism_meta"] = meta.model_dump()`；`source_type` 取 state 已有值，否则 `_infer_source_type` 按 `local_file_path` 后缀推断（pdf/md/xlsx/csv，无后缀默认 pdf）；随后 `apply_metadata` 把 `item_name`、`content_type.value`、`region`、`cultural_theme`、`category`、`source_type`、`extra`（存入 `extra_meta`）、`source_path`（`local_file_path`，上传文件本地路径，对齐需求"来源路径或资源链接"）回填到每个 chunk，字段与 tourism_chunks 集合显式字段一一对应（`tourism_meta_extract_service.py:104-116, 135-148, 158-164`）。

### 8. 步骤 5: 主体向量化并写入 Milvus tourism_entity
用 `llm_provider.embed_documents([meta.item_name])` 生成主体名（景点/文化主题/游记标题）的稠密+稀疏向量，调用 `upsert_entity(meta, file_title, dense_vector, sparse_vector, source_path)`（第 5 参为 `state["local_file_path"]`，即上传文件本地路径，写入实体行 `source_path` 字段，对齐需求"来源路径或资源链接"）：内部先 `prepare_tourism_entity_collection` 确保集合存在，再**仅按 `file_title`** 幂等删除旧记录后插入主体向量（同一主体的多个来源文件各自保留一条主体行，互不覆盖）。
注意：此步骤**未**包裹 try/except，失败会向上抛异常直接终止任务——代码注释明确「入库失败必须终止任务，否则会产生『chunks 有数据、entity 没数据』的半成品导入」（`tourism_meta_extract_service.py:152-157`）。

### 9. 单元测试

### 6. 步骤 3: 批量生成稠密+稀疏向量并回写（单批失败跳过）
调用 `llm_provider.embed_documents(vector_str_list)` 生成 BGE-M3（BAAI/bge-m3）稠密+稀疏双向量，逐条把 `dense_vector`、`sparse_vector` 写入 chunk 副本后收集；单个批次异常仅记录 warning「跳过，继续生成向量」，不影响后续批次（`embedding_service.py:46-54`）。
