# STORY.md — 文旅智能问答助手 项目汇报

## ① 用户意图对齐

- **目标受众**：部门项目汇报会——老板、团队同事、运营部门等**非技术人员**。代表部门介绍本项目从需求到落地的全过程。
- **核心目标**：讲完后观众相信"这个系统真的能用、而且被严格验证过"，并记住两件事：① 系统听得懂人话（意图识别是第一道闸门）；② 能帮用户把旅行行程安排好（天气、路线、当地时间三路信息并行汇成行程参考）。从而支持项目后续迭代与推广。
- **PPT 长度**：10 页。Hero 页 3 个（封面 P1、文旅规划 P6、结尾 P10），占比 30%。
- **视觉调性**：水墨文旅 × 现代清爽 / 克制留白 / 亲和易读（呼应项目导入页的水墨山水界面气质）。
- **内容边界**：
  - 必讲：需求背景 → 成果 → 系统全貌（总）→ 意图识别 → 文旅规划 → 资料上架流水线 → 整体流程 → 测试评估 → 总结展望。
  - 不讲：向量检索原理、模型训练、代码结构、部署细节；必要术语一律配白话比喻。
  - 禁碰：不编造数据。全部数字取自项目真实评测记录：40 道评测题（正 32 / 陷阱 6 / 模糊 2）、四轮准确率 87.5%→80.0%→95.0%→100%、检索命中率 100%、12 类文旅内容、6 种资料格式、2 个问答领域。
- **语言口径**：不出现"RAG / 向量 / Embedding / Milvus / RRF / rerank"等术语；用"知识库 / 图书馆 / 分诊台 / 精挑细选 / 贴标签"等比喻。

## ② 页面布局骨架

- **页面总数与分章**：共 10 页，线性叙事（无目录页、无章节扉页——短汇报不设目录，用 A 区阶段标签「需求 / 实现 / 验证 / 展望」+ 序号体现流程感）。目录声明章节数为 0，章节扉页数为 0，契约一致。
  - 需求阶段：P2
  - 成果一览：P3
  - 实现阶段（总分总）：P4（总）→ P5、P6（分：两大核心能力）→ P7、P8（分：后台流水线 + 整体流程，收束回到"总"）
  - 验证阶段：P9
  - 展望阶段：P10
- **Hero 页定位**：P1（封面）、P6（文旅规划，全篇内容高潮）、P10（结尾）。3/10 = 30%，落在 20–30%；任意两个 Hero 之间间隔 ≥ 1 页（1→6 隔 4 页，6→10 隔 3 页）✓。
- **rhythm 曲线**：P1 peak / P2 valley / P3 peak / P4 valley / P5 valley / P6 peak / P7 valley / P8 transition / P9 peak / P10 peak。连续 valley 最长 2 页（P4-P5），未超 3 ✓。
- **非对称版式预算（8/10 ≥ 40%）**：P1 全幅图+骑线文字、P2 非对称双栏、P3 巨型数字+洞察、P4 左标题+右内容、P5 左大图+右侧文字、P6 上大图+下方卡片、P7 左标题+右内容、P9 巨型数字+洞察。
- **对称版式预算（2 页）**：P8 图表+洞察、P10 全屏视觉+大标题。
- **版式约束自检**：相邻页版式全不同 ✓；`左大图+右侧文字`+`非对称双栏`合计 2 ≤ 4 ✓；`左标题+右内容` 2 次（P4、P7 不相邻）✓；`N卡片横排` 0 次 ✓；Hero 页无 N卡片横排 ✓。

### P6 核心能力二：把行程安排好——文旅规划
- title: 一句话，行程参考自动生成
- type: content | role: hero | rhythm: peak

### P7 深入后台：资料是如何「上架」的
- title: 六站流水线：从一份文件到可查资料
- type: content | role: supporting | rhythm: valley
- layout: 左标题+右内容（左 33% 标题栏 / 右 67% 六站步进）

- description: 收件员（接收文件/音频/图片）→ 翻译官（格式统一）→ 速记员（音频转文字、图片读画面）→ 整理装订（切成小段便于精准查找）→ 贴标签（标出"讲什么/在哪/属于谁"）→ 上架入库（立等可查）。判断落点：上架一次、全馆受益——同一份资料可被反复精准检索，这是"问得准"的物质基础。

### P8 一条问题的一生：整体流程
- title: 从提问到回答的六站旅程
- type: content | role: supporting | rhythm: transition
- layout: 图表+洞察（横向旅程图为主体 + 底部洞察框）

- anti_pattern: 禁止把六站画成竖向长列表；禁止洞察写成小字脚注
- description: 提问 → 分诊 → 找资料 → 精挑细选 → 组织回答 → 回复（带出处）；规划类问题在"找资料"旁并行加停三站：查天气、查路线、看时间，最后汇合。洞察框两条原则：①每个回答都标注出处，可溯源；②查不到就直说，绝不编答案（用陷阱题专门考过）。转场：流程跑通了——下一页，用考试证明它可靠。
