> 融合日期：2026-09-09　|　来源：`D:\xiangmu\helloagents-trip-planner`（HelloAgents 智能旅行助手）

## 一、一句话说明

将 helloagents-trip-planner 的「结构化 JSON 行程规划 + 高德 POI 事实核查」吸收进本 RAG 项目，
作为 **第四路行程规划能力** 提供独立 HTTP 服务与地图演示页；**淘汰 hello-agents 框架与 MCP 子进程**，
高德改走本仓库已在用的 REST Web 服务 API（`AMAP_API_KEY` 与 `route_tool_service.py` 同源）。

## 二、与本仓库既有「文字版行程」的关系

- 既有 `is_plan` 分支（`itinerary_service.py` + KB 检索）→ 保留不动，服务于 `/query` 对话流（含 40 题评测 plan 用例）。
- 新增「结构化行程」→ 独立图 `trip_plan_app` + 独立 `/trip/*` 路由，二者**完全解耦**，避免污染文旅/闲聊回归。

## 四、接口与配置

```text
POST /trip/plan            # 结构化表单（city/start_date/end_date/travel_days/...）
POST /trip/plan/nl         # 自然语言 → 自动抽取槽位 → 规划（body: {"query": "..."}）
GET  /trip/page            # 演示页（浏览器访问）
GET  /trip/amap-js-key     # 前端地图 Key 探测
```

配置项（`.env`）：
- `AMAP_API_KEY`（服务端 Web服务 Key，必填）
- `TRIP_AMAP_JS_KEY` / `AMAP_JS_SECURITY_CODE`（前端地图 Key + 安全密钥，可选；未配置时地图禁用但行程列表可用）
- LLM 复用现有 `OPENAI_API_KEY / LLM_DEFAULT_MODEL`（qwen-plus 等）

## 六、已知边界（后续优化方向）

1. 高德天气预报窗口约 3~4 天，行程超出窗口的日期 `weather_info` 可能缺项（前端按“-”展示，不编造）。
2. `/trip/plan` 为同步长请求（约 1~4 分钟）；前端以 5 段真实步骤文案展示进度。后续可升级 SSE 按节点推送（新增节点已完成 add_running/done 埋点，具备升级基础）。
3. 结构化行程生成 + 核查为真实数据强约束：采集失败/解析失败/无法核查时**显式返回 success=false + 可读错误**，绝不返回占位假行程。
4. 前端地图 Key 未纳入本仓库 `.env`（密钥独立管理）；请在 `.env` 填 `TRIP_AMAP_JS_KEY` 与 `AMAP_JS_SECURITY_CODE`。
5. 高德 QPS 限流治理（2026-09-09 已加）：`amap_gateway` 具备限流识别 + 线程安全节流（`AMAP_MIN_INTERVAL_MS`，默认 ≈4 QPS）+ 独立退避重试额度（`AMAP_RATE_LIMIT_RETRIES=3`）。
   详见 `docs/模块拆分与意图路由升级规划.md` 事项 C。**仍未做**：POI 核查并发化（C1 主体），以及"核查失败"与"查无此地"的区分（见该文档遗留项）。
