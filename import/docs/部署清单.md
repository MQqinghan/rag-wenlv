## 一、三个部署单元

| 服务 | 入口 | 端口 | APP_ROLE | 依赖安装组 | 是否加载模型 |
|---|---|---|---|---|---|
| 导入服务 | `app/api/http/import_server.py` | 8000 | `import` | `uv sync --extra import` | 是（Embedding） |
| 查询服务 | `app/api/http/query_server.py` | 8001 | `query` | `uv sync`（默认组） | 是（Embedding + Reranker） |
| 移动端 BFF | `app/api/http/mobile_gateway.py` | 8002 | `gateway` | 仅 4 个 Web 包 | **否**（纯转发） |

> 端口来源：`settings_config.py:20-21`（8000/8001）、`mobile_gateway.py:51`（8002）。

## 二、启动方式

### 2.1 本地（PyCharm，推荐开发态）

分别运行三个入口文件即可。**不设 `APP_ROLE` 时自检自动跳过**（角色回落 `all`），行为与改动前完全一致：

```
app/api/http/import_server.py     # 8000
app/api/http/query_server.py      # 8001
app/api/http/mobile_gateway.py    # 8002（需先起 query）
```

### 2.2 容器（推荐部署态）

```bash
# 仅三个应用服务（Milvus/Mongo/MinIO 用既有实例）
docker compose up -d --build

# 首次本地起全套（含 Milvus etcd/standalone、Mongo、MinIO）
docker compose --profile infra up -d
```

单服务构建：
```bash
docker build -f Dockerfile.import  -t rag-import:latest  .
docker build -f Dockerfile.query   -t rag-query:latest   .
docker build -f Dockerfile.gateway -t rag-gateway:latest .
```

## 三、配置分区（按角色消费）

| 角色 | 必需配置（缺失 = 功能不可用） | 推荐配置（缺失 = 能力降级） |
|---|---|---|
| `import` | `MILVUS_URL`、`MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_BUCKET_NAME`、`IMPORT_EGRESS_MODE` | `OPENAI_API_KEY`、`MINERU_BASE_URL`、`MINERU_API_TOKEN` |
| `query` | `MILVUS_URL`、`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`MONGO_URL` | `QWEATHER_API_KEY`、`AMAP_API_KEY`、`MCP_DASHSCOPE_BASE_URL` |
| `gateway` | 无（均有代码内默认值） | 无（T12 鉴权落地后补 `WX_APPID`/`WX_SECRET`/`JWT_SECRET`） |

**自检严格度**

| `ROLE_STRICT_CHECK` | 行为 | 适用场景 |
|---|---|---|
| 未设 / `false`（默认） | 缺必需配置打 ERROR 日志，**不阻断启动** | 本地 PyCharm 开发 |
| `true` | 缺必需配置**抛 RuntimeError 阻断启动**（fail-fast） | 容器 / CI（compose 已默认设 true） |

自检结果同时暴露在网关 `/health`：
```json
{"status":"ok","service":"mobile_gateway","role":"gateway","config_ok":true,"missing_required":[]}
```

## 五、基础组件

| 组件 | 生产建议 | compose `--profile infra` 内 |
|---|---|---|
| Milvus | 复用实例或云服务，改 `MILVUS_URL` | `milvus:v2.5.10` standalone + etcd + minio |
| MongoDB | 复用实例，改 `MONGO_URL` | `mongo:7` |
| MinIO | 复用实例，改 `MINIO_ENDPOINT` | `minio/minio:latest` |
| Redis（可选，T9） | 缓存后端：切 `CACHE_BACKEND=redis` 时需可达实例，多进程 / 重启后缓存全局共享 | `redis:7-alpine`（rag-redis） |
| 12306-MCP（可选，T14） | 跨城车次/票价数据源；失效即 `rail_gateway` 降级 `ok=False`，行程回落泛化表述。**上游非官方包装、无 SLA**，生产需监控 | 自建镜像（`Dockerfile.rail-mcp`，rag-rail-mcp，映射 8010→8000） |

## 六、部署检查单

- [ ] 目标机 `.env` 已按角色配齐必需项（或容器启动时 `-e` 注入）
- [ ] `APP_ROLE` 与 `ROLE_STRICT_CHECK=true` 已设置
- [ ] `./models` 已挂载且含 bge-m3 / bge-reranker-v2-m3
- [ ] 导入端已确认 `IMPORT_EGRESS_MODE` 档位（off/mask/full），见 `docs/分层防护清单.md`
- [ ] 网关 `QUERY_HOST` 指向可达的 query 服务（compose 内为服务名 `query`）
- [ ] 拉取 `GET /health` 确认 `config_ok: true`
- [ ] 若启用 Redis 缓存（`CACHE_BACKEND=redis`）：Redis 已启动且 `REDIS_URL` 可达（启动即 ping 探活，连不上 fail-fast；未启用则保持 `memory`）
- [ ] 若启用铁路（`RAIL_TOOL_ENABLE=True`）：12306-MCP 已启动且 `RAIL_MCP_URL` 可达（`GET /health` 返回 `status:healthy`）；同容器网络用 `http://rail-mcp:8000/mcp`，本机用 `http://127.0.0.1:8010/mcp`。不可达时 `rail_gateway` 降级 `ok=False`，行程回落到无铁路数据的泛化表述，**不阻断主链路、不编造票价**
