### 现象（用户复现原文）
新开对话提问：

> 在成都天府机场怎么到市区？到市区后怎么规划游览路线？

系统输出整份"跨城多日行程"，出现多处与用户意图不符的内容：

- 出发地脑补为 **深圳**："出发地→目的地：深圳→成都"；每日安排首日"从深圳出发，乘坐飞机前往成都天府机场"、末日"根据航班时间，前往成都天府机场，乘坐飞机返回深圳"。
- 日期未指定却被硬排为 **2026-09-05 至 2026-09-06（明天起 2 天 1 晚）**。
- **天数自相矛盾**：概览写"2天1晚"，实际每日安排有 3 段完整昼夜（抵达日 + 2 整天 + 返程日），违背 itinerary 模板"天数与实际安排必须一致"。
- 用户真实意图只是：① 天府机场→市区的交通怎么走；② 到市区后按什么路线游览（本地规划），完全不需要"从某地出发/返程"。

### 已完成的根因排查（结论性）
1. **全项目无硬编码默认出发地**：`app/**` 下"深圳"仅出现在
   `app/resources/prompts/tourism/rewritten_query_and_attractions.prompt:16` 的"延续类追问"示例文案（"深圳到杭州…"），非逻辑默认值。
2. **链路是纯 LLM 驱动**，嫌疑点有二（需抓 state 日志最终确认"深圳"从哪环进入）：
   - `app/resources/prompts/tourism/plan_extract.prompt`：origin 抽取规则允许在问题与改写参考都无出发地时填空，但缺少"严禁脑补默认城市"的负面约束；若 LLM 在 `rewritten_query` 阶段或抽取阶段自作主张，origin 就带上了"深圳"（进而 route/weather 与行程均受影响）。
   - `app/resources/prompts/tourism/itinerary_out.prompt`：规则 2/4 强制"每日安排必须覆盖完整往返（首日出发、末日返程）"。当 origin 为空时，这条规则会**诱导生成 LLM 自行编造一个出发地**来凑往返结构——这是最可能的主因。
3. **根因归类**：规划分支（方案B）只实现了"跨城出发→返程"一种语义，没有"抵达地本地规划 / 同城规划"模式。
   用户问句"在 X 机场怎么到市区 + 到市区后怎么玩"属于**已在目的地、只需进城交通 + 市内游览**，与现有模板语义不匹配。

### 期望行为（目标口径，具体话术待设计）
- 识别为"抵达地/本地规划"时：不出"出发地→目的地"跨城结构；不编排"首日从外地出发、末日返程"；不出现虚构航班/时刻。
- "机场→市区"按**目的地市内交通**处理：有【路线参考】或知识库交通指南资料则引用；无数据则写"建议用地图/购票平台查实时"（沿用现有禁编数字规则）。
- 用户未给日期：不强排"明天起 2 天 1 晚"，应提示天数可自选或按示例给出 1 天/多天两档，避免硬扣具体日期。
- 可顺带核查：概览天数与实际每日安排天数必须严格一致（本次 2 天 1 晚 vs 3 天内容的矛盾要一并杜绝）。

### 候选修复方案（择机实施，需先与用户确认口径）
- **方案A（轻，优先尝试，一个会话内）：纯 prompt 改造**
  1. `plan_extract.prompt`：新增负面约束——出发地只允许来自问题字面或历史行程；用户问题仅提到"在<城市>机场/车站 + 到市区/怎么玩"这类**已在目的地**的表达时，origin 必须为 ""，destination 归一为该城市名（如"成都"）；严禁按常见客源地脑补默认出发地。
  2. `itinerary_out.prompt`：把规则 2/4 改造成**条件分支**——origin 为空（或与 destination 同城）时进入"本地/抵达后规划"模式：不套往返结构、不写跨城大交通；用户未指定日期时不强排具体日期。同时保证：跨城规划（有明确 origin）、延续类追问（硬规则 7）行为不回归。
- **方案B（重，可选）：意图层增加"本地/同城规划"分类**
  在 is_plan 基础上再分"跨城多日 / 本地同城 / 纯交通咨询"，路由到不同答案模板或提示词；改动面大，需新增分支与回归用例。
- **实施前先补一步取证**：抓一次失败用例的 state 日志（`rewritten_query`、plan_extract 的 origin、itinerary 组装时的 history），确认"深圳"源头，避免改错环节。

### 回归测试清单（实施时覆盖，防把既有能力改坏）
1. 跨城多日：如"深圳到成都 5 天行程"（含明确出发地）→ 仍强制往返、日期沿用。
2. 延续类追问："换成公共交通/再安排一天/改坐飞机"→ 历史出发地目的地日期沿用不丢。
3. 本地/抵达后：本次复现问句 → 无跨城结构、无脑补出发地、机场进城给交通建议。
4. 纯交通咨询（若做方案B分类）："天府机场怎么到市区"→ 不输出整份多日行程。
5. 天气/路线工具降级时仍遵守禁编数字规则。
