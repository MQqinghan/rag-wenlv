# 分层防护清单（A3/A4 · T4 落地）

> 目的：把「外发可控/可审计」落到三层防护上，每层给出现状、规则与实现落点，
> 并作为 **P4（T10 移动网关 gateway_guard）分层防护的参照清单**——移动 BFF 在入口
> 复刻同一套分层，只是把「导入侧外发」换成「对外 API 面」。

## 二、越权拦截层（谁也不能绕过外发控制面）

| # | 规则 | 落点 | 状态 |
|---|---|---|---|
| A1 | **档位总开关**：off → 所有外发拒发（EgressBlockedError，不触网） | egress_gateway._guard | ✅ T3 |
| A2 | **供应商白名单**：目标 host 不在名单即拒（EgressDeniedError + 留痕）；IMPORT_EGRESS_ALLOWED_HOSTS 可收紧 | egress_gateway._guard / allowed_hosts | ✅ T3 |
| A3 | **出口唯一化**：dashscope SDK 只在网关内 import；langchain ChatOpenAI 外发只经网关 chat_invoke | egress_gateway（4 收口点改造） | ✅ T3 |
| A4 | **图片敏感预检**：VL 外发图片前本地 OCR 判敏感，命中即拦（IMAGE_SENSITIVE_GUARD，paddleocr 可用时生效） | egress_sanitizer.scan_sensitive_image → chat_invoke | ✅ T4（引擎依赖可选） |
| A5 | **词典/敏感口径扩展点**：IMPORT_EGRESS_SENSITIVE_WORDS 追加内部代号与重点人名 | egress_sanitizer._dict_words | ✅ T4 |
| **P4 复用提示** | 鉴权（openid/token）+ QPS 限流 + 与 A2 同构的“能力白名单” | mobile_gateway.gateway_guard | ⬜ T10/T12 |

## 附：当前已知缺口（不阻塞，按序收敛）

1. **MinerU PDF 解析外发点**：pdf_parse_service 直连 requests 至 mineru.net，尚未收口进 egress_gateway。
   建议在 T5/T8 并行窗口统一评估（入库白名单已含 mineru.net，功能不受影响，只是少一层审计/脱敏）。
2. **本地 OCR 引擎**：paddleocr 未安装 → IMAGE_SENSITIVE_GUARD 当前处于"可用即启用"的空转态（日志告警一次）；
   安装 paddlepaddle + paddleocr 后自动生效，无需改码。
3. **纯 18 位数字身份证与银行卡正则无法完全消歧**：必要时用词典词先行覆盖（见 egress_sanitizer 注释）。
4. **音频外发已移除**：单域化后不再接入 ASR/音频，原"音频允许外发"约束不再适用。
5. 审计的 task_id 目前由调用方未传（audit 记 document）；导入任务侧如需按任务回溯可在 T5 后把 task_id 透传进 4 个收口点。
